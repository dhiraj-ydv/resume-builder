# Resume Research Skill

## Goal

Build an evidence pack before writing a role-specific resume.

## Inputs

- Target role or job description, when available
- Existing resume variants in the user's workspace (`resumes/`)
- The user's `profile.json` and any materials they provide (portfolio, writeups, repos)
- Repository or document context the user explicitly makes available

## Process

1. Extract the target role's top responsibilities, hard skills, domain signals, and likely screening keywords.
2. Collect projects, product decisions, system design, outcomes, constraints, and technical depth that map to those requirements.
3. Create an evidence matrix with: requirement, supporting evidence, source, confidence, and whether a measurable result is verified.
4. Prefer recent and role-relevant evidence over older generic material.
5. Identify gaps explicitly. Never fill gaps with invented claims.

## AI-specific evidence to look for

Look for real examples of AI product work, LLM integrations, structured extraction, OCR/document intelligence, agents, automation, retrieval/search, evaluation, production reliability, cost/latency decisions, and human review loops.

## Output expectations

The research stage should produce a short prioritized set of facts that can be defended in an interview. Separate verified evidence from hypotheses or wording ideas.

## Red flags

- Metrics with no source
- Technologies inferred only from buzzwords
- Inflated ownership such as “led” when contribution level is unclear
- Repackaging a concept/writeup as a shipped production system
- Using AI terminology that cannot be tied to a concrete example
